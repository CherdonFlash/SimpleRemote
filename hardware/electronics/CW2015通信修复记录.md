# CW2015 通信修复记录

日期：2026-09-12。

## 原因与更正

板上主控为 STM32F103C6，ST-Link 识别设备 ID 0x412、32 KiB Flash。
该型号只有硬件 I2C1，没有硬件 I2C2。原驱动把 PB10/PB11 配为 AF_OD
并访问 I2C2，运行时这两脚读低，I2C2 寄存器始终读零，通信超时。
关闭原初始化后，两脚浮空输入时均为高。

原先“配置为 AF_OD 就能排除 MCU 拉低”“必定是芯片或焊接故障”的判断错误。
AF_OD 的输出受复用功能控制，不能仅凭 GPIO 输出锁存置高就认定管脚已释放。
本次使用普通开漏 GPIO 后同一块板立即读通，未要求更换芯片或修改连线。

来源：[ST STM32F103x4/x6 数据手册](https://www.st.com/resource/en/datasheet/cd00210843.pdf)。
原网名 IIC2_SCL / IIC2_SDA 仅是网络标签，不代表 F103C6 具备该外设。

## 修复实现

- PB10/SCL、PB11/SDA 使用 GPIO_Mode_Out_OD，速率配置 2 MHz。
- 写 1 释放总线，由原有 4.7 kΩ 电阻上拉；写 0 拉低，绝不推挽强拉高。
- 以 SysTick 实现至少 5 us 半周期，时钟低于或等于约 100 kHz，允许中断延长周期。
- 实现 START、重复 START、0xC4/0xC5 地址、ACK/NACK、STOP 和连续双字节读取。
- SCL 等待有 2 ms 超时；总线异常时最多补 9 个时钟并尝试 STOP，退出时释放双线。
- 上电读取 VERSION、MODE；必要时退出睡眠。每秒读取电压、SOC、RRT。
- 出错后下次周期重新初始化；保留最后有效业务读数，OLED 显示 --%。
- 取消 PB1 电压兜底调用：V1.1 已无对应分压，之前约 3.03 V 的 ADC 数值不能作为电池电压依据。
- 不写 BatteryInfo 电池曲线、不反复 quick start，避免把通信修复与 SOC 标定混为一谈。

## 实测验证

Keil 完整 Rebuild：0 error、0 warning。
Code 24526 B，RO-data 2394 B，RW-data 72 B，ZI-data 3864 B。
ST-Link 烧录及 Flash 校验成功，随后自动复位运行。

最终版本连续运行的快照：44 次尝试、44 次成功、0 次错误。
另执行 3 次 MCU 软件复位，各次复位后约 3 秒读到 4 次尝试、4 次成功、0 次错误。

| 项目 | 实测 |
| --- | --- |
| VERSION | 0x73 |
| 电压 | 3945～3946 mV |
| SOC | 整数70%，小数约0.6% |
| 驱动状态 | CW2015_OK（0） |
| GPIOB_CRH | 0x44446633，PB10/PB11普通开漏输出 |
| GPIOB_IDR | 0xFF38，PB10/PB11均为高 |
| 总线空闲诊断 | bus_levels=3 |
| RRT 原始字段 | 0x1FFF，本次不将其解释为可信剩余分钟数 |

诊断符号（最终本次 AXF，重新链接后应重新解析地址）：

- g_cw2015_data：0x200008D8，10 B，status 为偏移9的单字节枚举。
- g_cw2015_diag：0x200008E4，7个32位字段，依次为 attempts、successes、
  errors、last_success_ms、stage、last_register、bus_levels。

软件复位测试不会切断电池对 CW2015 的供电，因此完整断电再上电尚未在本次自动测试中验证。
通信已验证；实际容量/SOC精度仍需匹配电池曲线和实物放电测试确认。
